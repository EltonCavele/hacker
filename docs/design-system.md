# Design system

UI is built with [shadcn/ui](https://ui.shadcn.com) (Radix + Tailwind CSS v4), but the components are **owned by this repo**: they are copied into `components/ui` and edited by hand. Treat them as our code, not as a dependency.

See every component live at `/design-system` (development only, `app/design-system/page.tsx`).

## Where things live

| What                                               | Where                                               |
| -------------------------------------------------- | --------------------------------------------------- |
| Design tokens (colours, radius)                    | `app/globals.css` (`:root` = light, `.dark` = dark) |
| Primitive components                               | `components/ui/*.tsx`                               |
| Class merging helper `cn()`                        | `lib/utils.ts`                                      |
| Feature-specific UI                                | `features/<feature>/components/`                    |
| App-wide, non-primitive UI (theme provider/toggle) | `components/`                                       |
| Live reference page                                | `app/design-system/page.tsx`                        |

Primitives in `components/ui` know nothing about the product (no data fetching, no feature imports). Anything that knows about tasks, payments, etc. belongs in `features/`.

## Rules

1. **Use tokens, never raw colours.** Write `bg-primary`, `text-muted-foreground`, `border-border`, not `bg-zinc-900` or `#fff`. Rebranding then means editing `globals.css` only.
2. **Use a component before writing markup.** Need a button, field, badge, card or alert? Import it from `components/ui`. Do not hand-roll `<button className="...">`.
3. **Compose with `className`.** Every component accepts `className`, merged through `cn()`. Use it for layout (`w-full`, `flex-1`), not to restyle colours; add a variant instead.
4. **Variants over one-off classes.** If you repeat the same override twice, add a variant in the component's `cva` definition.
5. **Accessible by default.** Inputs have a `Label`, icon-only buttons have `aria-label`, state is never conveyed by colour alone.

## Components

Pick by the job, not by the look.

**Actions and status**

| Component | Use it for                                                                                                                                | Don't use it for             |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `Button`  | Any action. `isLoading` for async; `isAnimated` + `status` to confirm the result (`onSuccess`/`onError`); `asChild` + `Link` to navigate. | Plain inline links.          |
| `Badge`   | Short status/category (`success`, `warning`, `info`, `destructive`).                                                                      | Clickable things, long text. |

**Forms** (always pair with `Label`)

| Component    | Use it for                                                                                                                                                                                                                                                                 | Don't use it for                                              |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `Input`      | Single-line text.                                                                                                                                                                                                                                                          | Long text, picking from a list.                               |
| `Textarea`   | Multi-line text.                                                                                                                                                                                                                                                           | Short values.                                                 |
| `Select`     | One value from ~4–15 options.                                                                                                                                                                                                                                              | 2–5 visible options (`RadioGroup`), actions (`DropdownMenu`). |
| `RadioGroup` | Exactly one of 2–5 visible options.                                                                                                                                                                                                                                        | Long lists.                                                   |
| `Checkbox`   | Yes/no or multi-select; needs a Save.                                                                                                                                                                                                                                      | Instant settings (`Switch`).                                  |
| `Switch`     | Setting that applies immediately.                                                                                                                                                                                                                                          | Forms with a Save button.                                     |
| `Form`       | Any form with validation: react-hook-form + zod. `useZodForm(schema)`, then `FormField` → `FormItem` → `FormLabel` + `FormControl` + `FormMessage`; `FormError` for server errors (`setError("root")`), `FormSubmit` for the loading button. Works with every field above. | A lone input with no rules.                                   |

**Overlays**: choose by how much they interrupt.

| Component      | Use it for                                                                                                                                                                                                                                                                                                                                        | Don't use it for                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `Dialog`       | Focused task in a modal (edit, short form, details). Below `sm` it is a bottom sheet (swipe the handle down to close); wrap long content in `DialogBody` so only it scrolls (header and footer stay fixed); add `isExpansible` to let the sheet be swiped up to full height. `size` (`sm` default, `md`, `lg`, `xl`) sets the desktop width only. | Destructive confirmations, long flows. |
| `AlertDialog`  | Confirming destructive/irreversible actions.                                                                                                                                                                                                                                                                                                      | Forms, information.                    |
| `Sheet`        | Side panel keeping page context (filters, details, mobile nav).                                                                                                                                                                                                                                                                                   | Confirmations.                         |
| `DropdownMenu` | List of actions from a button (row actions, user menu). `size="lg"` on items gives roomier rows for account/navigation menus.                                                                                                                                                                                                                     | Choosing a form value.                 |
| `Popover`      | Small interactive floating content.                                                                                                                                                                                                                                                                                                               | Plain hints, blocking tasks.           |
| `Tooltip`      | Short label for icon-only buttons.                                                                                                                                                                                                                                                                                                                | Essential info, interactive content.   |

| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |

Each file in `components/ui` starts with a comment saying when to use it and when not to. Keep that comment up to date.

## Page states

Every screen handles four states the same way:

| State     | Use                                                                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Loading   | `loading.tsx` in the route segment with `Skeleton`s shaped like the content (see `app/(dashboard)/loading.tsx`).                                       |
| Empty     | `EmptyState` with a next-step action.                                                                                                                  |
| Error     | `error.tsx` rendering `ErrorState` (`components/error-state.tsx`); it reports to Sentry and keeps the surrounding layout. Inline failures use `Alert`. |
| Not found | `not-found.tsx`, or call `notFound()` from the page.                                                                                                   |

## Colour tokens

`background`, `foreground`, `primary`, `secondary`, `muted`, `accent`, `border`, `input`, `ring`, `card`, `popover`, `destructive`, plus the status tokens added for this project: `success`, `warning`, `info` (each with a `-foreground` pair). Charts and sidebar tokens exist for later use.

The Folha Viva chief app wraps in `.folha-app` and overrides the same tokens (cream, forest, leaf-green). Auditoria, CEDSIF and the public panel use the dashboard shell (sidebar and page header) and the global tokens.

Dark mode is class-based and managed by `next-themes` (`components/theme-provider.tsx`, mounted in `app/layout.tsx`, following the OS by default). Drop `<ThemeToggle />` (`components/theme-toggle.tsx`) anywhere to let users switch.

`TooltipProvider` and `Toaster` are mounted once in `app/layout.tsx`; don't add them elsewhere.

## Adding a component

```bash
npx shadcn@latest add dialog
```

Then, before committing:

1. Open the new file. The CLI may import `cn` from `"cn"`: change it to `@/lib/utils` and run `npm uninstall cn` if it was installed (we use `clsx` + `tailwind-merge`).
2. Customise it: remove variants and sizes we don't need, replace raw colours with tokens.
3. Add a short "Use it for / Don't use it for" comment above the component.
4. Add a section to `app/design-system/page.tsx` and a row to the table above.

## Customising the look

- Change colours and `--radius` in `app/globals.css`.
- Change a component's shape, sizes or variants in its own file in `components/ui`.

## Interface details (from detail.design)

- **No browser "back" on sideways scroll**: `html, body { overscroll-behavior-x: none }`, and `overscroll-x-contain` on the `Table` container.
- **Better line breaks**: headings use `text-wrap: balance`, paragraphs/lists use `text-wrap: pretty` (global, in `@layer base`).
- **Adaptive text colour**: `text-adaptive` picks black or white for a `--surface` colour via CSS relative colour syntax (no JS).
- **Progressive blur edge**: `<ProgressiveBlur side="top" />` as a sibling of the scroller (7 masked blur layers + surface tint).
- **Dynamic theme colour**: `<ThemeColor />` (mounted in the layout) keeps `<meta name="theme-color">` equal to the page background across theme changes; `useThemeColor("#4f46e5")` overrides it while a screen is mounted.
- **Scroll landmark**: `<ScrollLandmark />` (page) or `<ScrollLandmark target={ref} />` (container); turns into "back where you were" after jumping to the top.
- **Blurred image appearing**: `<BlurImage src alt wrapperClassName="aspect-video" />` fades from blur to sharp on the `load` event (cache-safe, no React state).
- **Blurred icon transition**: `Button isAnimated` swaps spinner → check/cross by blurring the outgoing icon out while the incoming one comes in from a blur (all icons share one slot; only `data-active` flips). The slot collapses when empty.
- **Shake a disabled button**: `<Button disabled>` uses `aria-disabled` (still focusable): clicking swallows the action and shakes the button. `isLoading`/status keep the native `disabled` (no shake).
- **Morphing button to input**: opt-in via `<Button input={{ onSubmit, placeholder, width }}>`. The button's width animates into a text field (cross-fade, focus moves in); Enter submits (async OK: spinner, a rejection keeps it open as invalid), Esc or leaving it empty collapses it back.
- **Hold to reveal shortcuts**: add `<ShortcutHint keys={["mod", "S"]} />` inside a `relative` control.
- **Name-derived placeholder**: derive the example of a field from what the user already typed (see the Email demo).
- **Label focuses its field**: always pair `Label` with `htmlFor`/`id`; never break it.
